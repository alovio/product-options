# Advanced Product Options for WooCommerce — v1 (Free Tier) Implementation Plan

> **For agentic workers:** REQUIRED: Use superpowers:subagent-driven-development (if subagents available) or superpowers:executing-plans to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship a freemium WooCommerce plugin that lets store owners add per-product custom fields via a modern drag-drop builder with live preview, with single-condition conditional logic and fixed-fee price add-ons that flow correctly into cart and order.

**Architecture:** PHP back end (PSR-4, namespace `APO\`) handles field storage (product meta JSON), a REST API for the builder, front-end rendering on the product page, and HPOS-compatible cart/order integration. A React app (`@wordpress/scripts` + `@wordpress/components`) is the builder UI mounted in the product editor; a small vanilla-JS bundle drives front-end conditional logic and live price updates. Pure-logic classes (schema validation, conditional evaluation, price calculation, value validation) are unit-tested with Brain Monkey; WordPress/WooCommerce integration is tested with `@wordpress/env` + PHPUnit. Pro features attach through `apply_filters` extension points seeded in v1.

**Tech Stack:** PHP 7.4+ (target 8.x), WordPress 6.4+, WooCommerce 8.x (HPOS), Composer (PSR-4 autoload, PHPUnit, Brain Monkey), `@wordpress/scripts` (webpack/Babel/Jest), React, `@wordpress/components`/`@wordpress/data`/`@wordpress/api-fetch`.

**Conventions (user git rules):** stage specific files only — never `git add -A`/`.`; no `Co-Authored-By` lines in commits; do not bump the plugin Version header except on real releases. Initial work commits to `main` of the new repo; later feature chunks may branch.

**Field-group data model (the contract every layer shares).** Stored as JSON in product meta key `_apo_field_group`:

```json
{
  "version": 1,
  "fields": [
    {
      "id": "fld_engrave",
      "type": "text",
      "label": "Engraving text",
      "required": false,
      "price": 5.0,
      "options": [],
      "condition": {
        "field": "fld_wantengrave",
        "operator": "is",
        "value": "yes",
        "action": "show"
      }
    }
  ]
}
```
- `type` ∈ free set: `text, textarea, number, checkbox, radio, select, price` (fixed fee).
- `price` = fixed fee added when the field is "active" (checked / non-empty / option selected). Pro adds formulas.
- `condition` is `null` in free for all-but-one dependency (single condition). `operator` ∈ `is, is_not` in free (Pro adds numeric/contains). `action` ∈ `show, hide, require`.
- `id` is a stable slug; cart/order keys derive from it.

### Task 16: OptionSanitizer + CartIntegration (HPOS-safe)

**Files:** Create `includes/Cart/OptionSanitizer.php`, `includes/Cart/CartIntegration.php`; wire in `Plugin::boot()`; Test `tests/php/Unit/OptionSanitizerTest.php`, `tests/php/Integration/CartIntegrationTest.php`

**Step A — shared sanitizer (pure unit, the single input source for BOTH validation and cart data):**
`OptionSanitizer::sanitize( array $group, array $raw ): array` — type-aware: `text`→`sanitize_text_field`, `textarea`→`sanitize_textarea_field`, `number`→`floatval`, `checkbox`→bool, `select`/`radio`→value must be in that field's options else dropped. Returns map keyed by field id. Unit-test it (stub the WP sanitizers via Brain Monkey).

**Step B — CartIntegration hooks (the full, correct money path):**
- `woocommerce_add_to_cart_validation` → `$opts = OptionSanitizer::sanitize($group, $_POST['apo'] ?? [])`; run `Validator::validate`; `wc_add_notice` each error and return `false` on failure. (Uses the **same** sanitized source as the data hook.)
- `woocommerce_add_cart_item_data` → store `$cart_item_data['apo'] = [ 'options' => $opts, 'base_price' => (float) $product->get_price(), 'unique_key' => md5( wp_json_encode( $opts ) ) ]`. The `unique_key` makes **identical selections merge quantity** and **different selections stay separate lines**.
- **`woocommerce_get_cart_item_from_session`** ← REQUIRED: re-attach/normalize the `apo` array when the cart is rebuilt from session on each request (otherwise multi-request carts silently lose data/pricing).
- `woocommerce_before_calculate_totals` → for each item with `apo`, **always recompute from the stored base**: `$item['data']->set_price( $apo['base_price'] + PriceCalculator::addon_total( $group, $apo['options'], wc_get_price_decimals() ) )`. **No run-once static guard** (totals legitimately recalc on qty/coupon change); recomputing from `base_price` is idempotent and avoids price stacking.
- `woocommerce_get_item_data` → append human-readable, **escaped** label/value rows for cart/checkout display.
- `woocommerce_checkout_create_order_line_item` → `$item->add_meta_data( $human_label, $human_value )` (display-formatted, not raw `apo[id]` keys) so order/email/admin show clean rows. HPOS-safe via CRUD — no direct SQL.

  - **reload cart from session, then assert price/meta survive** (covers the session hook);

## Pro extension points seeded in v1 (do not build Pro now — just leave the seams)
- `apply_filters( 'apo_field_types', $types )` — Pro registers file/date/swatch/slider/signature.
- `apply_filters( 'apo_allowed_operators', [...] )` / `'apo_allowed_actions'` — Pro adds numeric/`contains`, multi-condition.
- `apply_filters( 'apo_addon_total', $total, $group, $submitted )` — Pro injects formula/percentage/qty pricing.
- `do_action( 'apo_render_field_{type}', $field, $value )` — Pro renders advanced field types.
- Field-group JSON `version` key — migration headroom.

## Out of scope for v1 (deferred to v2+)
Multi-condition AND/OR, price formulas, file upload, date/time, color/image swatch, slider, signature, global add-on groups, multi-step wizard, import/export, drag-reorder polish, page-builder integrations.

## Risks to watch during execution
1. **Price double-application** in `before_calculate_totals` (recursion / multiple calls) — guard and assert in integration test.
2. **Theme/page-builder markup variance** — render via standard WooCommerce hook; document known-good themes; defer deep integrations.
3. **No-JS / cached pages** — server-side initial visibility + server-side validation are authoritative; JS is enhancement only.
4. **Tax/currency correctness** — use WooCommerce price APIs (`set_price`, `wc_format_decimal`), never hand-format money.
